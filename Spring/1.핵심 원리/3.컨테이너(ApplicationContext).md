## BeanFactory vs ApplicationContext
- Bean: 스프링이 제어권을 갖고 생명주기를 관리하는 오브젝트
- BeanFactory: [[2.IoC·DI|IoC]] 기본 기능(Bean을 생성하고 관계를 설정)하는 클래스
	- **애플리케이션 내 모든 Bean에 대한 종합 팩토리**
		- [[2.디자인 패턴#팩토리|팩토리 패턴]]
	- `configuration metadata`
		- IoC 설정에 필요한 정보를 담고있는 클래스/파일
		- BeanFactory가 읽어서 사용한다
	- 별도 설정을 하지 않으면 Bean을 [[2.디자인 패턴#싱글톤|싱글톤]]으로 생성한다
		- 매번 새로 생성하도록 설정 가능
		- 왜?
			- 일반적으로 JavaEE 기술 기반의 서버 환경에서 사용
			- 수많은 요청을 처리 → 매번 새로 만들면 부하
	- **중요) 일반적인 싱글톤 구현 방식을 사용하는 것은 아님**
		- `싱글톤 레지스트리` → 스프링 자체적으로 싱글톤 **형태의** 오브젝트를 생성/관리하는 기능
		- 싱글톤의 단점 (private 생성자, 테스트 제한, 객체지향 무시 등)이 해소된다
- ApplicationContext(= 스프링 컨테이너)
	- `interface ApplicationContext extends BeanFactory`
	- BeanFactory 기능에 더하여, 애플리케이션 전반에 걸쳐 모든 구성요소의 제어작업을 담당
	- e.g.
		- 자동생성
		- 오브젝트에 대한 후처리
		- 정보의 조합
		- 설정 방식의 다변화
		- 인터셉팅
	- 'IoC 엔진'


- 컨테이너, 스프링 컨테이너, IoC 컨테이너: 추상적인 개념 (역할)
- BeanFactory, ApplicationContext: 스프링 내에서 실제 해당 기능을 정의한 인터페이스
