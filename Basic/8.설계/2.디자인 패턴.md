## 싱글톤
- 구현방식
	- ```java
	// 1. 기본
	public class MySingleton {
	  private static MySingleton INSTANCE; // 하나만
	  
	  // 외부에서 생성자 호출하지 못하도록
	  // 인스턴스가 하나뿐이므로 생성자도 하나
	  private MySingleton(...) {
	    ...
	  }
	  
	  // 외부에는 인스턴스 제공 메소드만 오픈
	  // synchronized → 여러 스레드에서 동시 실행할 수 없게 방지
	  public static synchronized MySingleton getInstance() {
	    if (INSTANCE == null) INSTANCE = new MySingleton(...);
	    return INSTANCE;
	  }
	}
	  ```

- 단점
	- 하나의 priavte 생성자만 사용 → 상속할 수 없다
	- 만들어지는 방식이 제한적이라 mocking이나 내부 구조 조작이 불가 → 테스트 작성이 어렵다
	- 서버 환경에서 싱글톤을 보장할 수 없다
		- [[4.클래스로더|클래스로더]] 구성방식에 의해서
		- 애플리케이션이 여러 서버 (=JVM)에서 구동되어서
	- 전역 상태로 사용되기 쉽다 → 객체지향스럽지 않고 통제가 어렵다
- 원칙
	- 공유하면 안되는 상태 (수정 가능한 필드 등)를 두면 안된다
		- readonly인 경우 괜찮(을 수 있)음
	- **스레드마다 달라질 수 있는 값은 필드 대신 지역 변수, 파라미터 등에 배치한다**

## 전략
- 기능 맥락 (context)에서 변경되는 부분을 '전략' **인터페이스**로 분리한다
- context를 사용하는 클라이언트에서 전략의 구현을 선택할 수 있게 한다
	- 일반적으로 context의 생성자로 제공한다

## 템플릿 메서드
- 고정된 기능은 슈퍼클래스에서, 달라지는 기능만 서브클래스에서 결정(구현)한다
- 추상 메소드: 서브클래스에서 반드시 결정해야 하는 기능
- hook method: 서브클래스에서 선택적으로 교체할 수 있는 기능. default로 기본값 제공
- vs 전략 패턴
	- 템플릿 메서드 패턴은 상속한 서브클래스를 사용한다
	- 전략 패턴은 상속 대신 컴포지션으로 전략을 갈아끼운다
- 팩토리 메소드 패턴
	- 생성 기능의 구현을 서브클래스에 위임하는 메소드
		- **주로 인터페이스 타입을 반환**
		- 슈퍼클래스는 구현체 신경쓰지 않고 인터페이스로 정의된 기능만 사용한다
	- 템플릿 메소드 패턴의 흐름과 유사
		- 공통 기능은 슈퍼, 달라지는 기능(생성)은 서브
	- 일반적인 팩토리 메소드 (`static MyObject of(...)`), 팩토리 패턴이랑 다른 개념
