## 기본형 vs 참조형

기본형
- byte: 1바이트 표현
- short (잘 안 씀)
- char: 유니코드 표현에 주로 사용
- int
- long
- float: 굳이 쓸 이유 없음
- double: 리터럴 표현 시 E 사용 가능 `double x = 0.12E-2`
- boolean
참조형
- 객체의 주소를 참조하는 타입
- 초기화 없이 선언 시 기본값 null
- String
	- String → 기본형: `Wrapper.parseXxx(str)`
	- 기본형 → String: `String.valueOf(val)`

## 오토박싱·언박싱
- 오토박싱: 기본 타입의 값을 래퍼 타입 객체로 만들기
	- `Integer i = 3`
- 언박싱: 래퍼 타입의 값을 기본 타입 변수로 만들기
	- `int i = Integer.of(3)`

## String 불변성과 String Pool
- String은 내부 문자열을 수정할 수 없음
- `String a = "ABC"; a += "DEF";`
	- 기존 String 객체의 값을 ABCDEF로 변경하는 것이 아님
	- ABCDEF라는 새로운 String 객체를 만들고 a가 해당 객체를 참조하게 하는 것

## `"=="` vs `equals`
- == 연산자 (동일 비교)
	- 기본형 변수는 값을 비교
	- 참조형 변수는 번지를 비교 → 같은 의미를 갖고 있어도 참조하는 번지가 다르면 다른 것으로 간주
	- null == null → true
- equals
	- Object의 equals 메소드를 상속해서 비교한다
	- Object 기본 구현은 == 연산자를 통해 번지를 비교하는 것 (동일 비교)
	- 클래스를 정의할 때 일반적으로 내부 데이터를 비교하도록 override한다 (동등 비교)
	- 아래 hashcode도 함께 재정의하는 것이 일반적

## hashCode 계약
- hashcode: 객체를 식별하는 정수
	- 메모리 번지를 **이용해서** 해시코드를 생성한다. 번지 자체는 아님
- equals 오버라이드 할 때 hashcode도 같은 구조로 재정의하는 것이 좋다
	- **이유: Hash 기반 자료구조들이 hashcode()와 equals()를 같이 사용함**
	- hashcode 재정의하지 않으면 동등 변수가 다르다고 판단되어 중복 저장

## final
- 필드, 상수, 변수: 초기화 또는 생성자 통한 생성 이후 새 값 **대입** 불가
	- 참조형 변수일 경우 내부를 수정하는 것은 가능
- 클래스: 상속 불가 → 자식 클래스 생성 불가
- 메소드: override 불가
## static
- 필드, 메소드: metadata 영역의 클래스에 고정적으로 위치하는 멤버
	- 객체 생성 없이 바로 접근 가능
	- 인스턴스 필드를 사용하지 않는 메소드는 정적 메소드로 선언하면 좋음
- 블록
	- 클래스가 메모리로 로딩될 때 자동으로 실행
	- 클래스 내부에 여러 개가 있는 경우 선언된 순서대로 실행
	- 주로 복잡한 정적 필드 초기화에 사용
- 내부에서 인스턴스 필드/메소드 사용이나 this 사용 불가
- 멤버 클래스
	- 접근 제한자에 따라 접근 범위가 달라진다
		- public: 외부 패키지에서 접근 가능
		- default: 현재 패키지에서 접근 가능
		- private: 외부 클래스에서만 접근 가능
	- 주로 외부 클래스와 함께 사용되는 경우가 많으므로 default(package)나 public 사용

## 접근 제어자
- public: 제한 범위 없음
- protected: 상속 받은 자식 클래스에서 접근 가능. **같은 패키지에서도 사용 가능**
- default: 같은 패키지에서만 접근 가능
- private: 해당 객체 내부에서만 접근 가능
