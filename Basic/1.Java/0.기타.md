JDK: 개발환경 위주
JRE: 실행환경 위주
DTO: 계층 간 값 전달로만 쓰이는 객체
VO: "값"을 표현하는 객체 → DTO와 다르게 로직이 있어도 자연스럽다

### 팁
- null 체크는 가능하면 `Objects.requireNonNull(obj)` 사용
	- null이면 NPE를 던진다

- Comparator → Interface 설계 GOAT
	- default, static, ...

- Interface의 default 메소드는 override 가능

- 모델 → DTO 매핑이 복잡한 경우 MapStruct를 검토

- 의존성 주입에 인터페이스를 사용하지 않아도 되는 경우
	- 구현체마다 성격이 많이 다른 경우 (MyBatis, JPA, JDBC, ...)
	- 어차피 구현체가 바뀌면 코드도 다 바뀐다
	- 강결합을 허용하고 클래스로 바로 주입

- 전략패턴 기반으로 '정책'을 정의하는 클래스는 XxxPolicy 가 네이밍컨벤션

- 확장을 고려한 코드 작성 시 (e.g. Enum), '조용한 실패' 방지를 위해 등록되지 않은 값은 예외를 던지게 하는 게 좋다
	- ```java
	  public enum Level {
	    ...
	    
	    public static Level valueOf(int value) {
		  return switch(value) {
		    case 1 -> BRONZE;
		    case 2 -> SILVER;
		    case 3 -> GOLD;
		    
		    // 이런거
		    default: throw new IllegalArgumentException()
		  }
	    }
	  }
	  ```
